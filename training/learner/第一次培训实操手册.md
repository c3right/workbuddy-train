# 第一次培训实操手册

> 适用对象：第一次从“网页聊天型 AI”转向 WorkBuddy 的同事  
> 本次目标：**不是学完所有功能，而是亲手跑通一次 Agent 工作闭环。**

---

## 先进入角色：你刚接了一个有点头大的项目

你刚入职一家咨询公司，成为一名研究员。

上午刚坐到工位没多久，项目经理就在群里 @ 你：

> **“新岚汽车这个项目你先接一下，周五要开阶段会。前面的同事临时被调走了，资料都在文件夹里，你先尽快熟悉一下。”**

你打开项目目录一看：客户背景、项目交接记录、四个区域的访谈、Excel 数据、图表、以前项目的参考简报……文件不少，而且说法还不完全一致。

前任同事的交接记录也很真实：

- 有些事情已经确认；
- 有些只是客户自己的判断；
- 有些是经销商的说法；
- 有些他自己也记不太清；
- 还有几个数字连出处都没找到。

项目经理没有让你今天就给答案，只说了一句：

> **“你先把情况搞明白，别急着下结论。”**

如果按以前的做法，你大概会先把十几个文件逐个打开，一边看一边做笔记，再慢慢整理。

这时你想到：

> **既然现在有 WorkBuddy，能不能先让 AI 和我一起把这个项目接下来？**

接下来，你就把自己当成这个刚接手项目的研究员。

**不是来看 WorkBuddy 有什么功能，而是真正带着它，把这项工作一步一步往前做。**

---

## 0. 先记住这一张图

```text
先选对工作目录
→ 让 Agent 先看懂资料
→ 把大工作拆成小任务
→ 说清楚：做什么 / 有什么 / 怎么样
→ 让 Agent 生成或修改真实文件
→ 人检查事实、逻辑和边界
→ 具体指出问题，继续改
→ 重要文件保留 v1 / v2
→ 换了一件事，就换一个 Task
```

你不需要背术语，也不需要追求“神 Prompt”。这次只练正确的工作方法。

---

## 1. 打开项目

在 WorkBuddy 中选择整个：

`新岚汽车渠道研究项目/`

作为这次工作的目录。

目录中有：

- `00-项目背景/`：项目是什么、客户在问什么、研究边界是什么；
- `01-待处理资料/`：交接记录、四份区域访谈、Excel、图片；
- `02-参考样例/`：以前项目的一份内部简报，可以参考结构和信息密度；
- `03-output/`：你后面生成的成果放这里。

**先记住一个原则：原始资料不要随手改。**

---

# Exercise 0｜先看看这是个什么项目

你刚接手项目，第一反应通常不会是马上写报告，而是先搞清楚自己接到了什么。

可以很自然地说：

```text
我刚接手这个项目，你先帮我看看现在大概是什么情况。
告诉我这看起来是个什么项目、手头都有哪些资料、各自大概是干什么的。

先别动文件，也不用急着出正式成果，我想先有个整体印象。
```

### 你要观察什么

- 它有没有真的去看当前项目，而不是只回答一些泛泛的常识；
- 它能不能说清楚手头大概有哪些资料；
- 它有没有遵守“先了解，不急着动手”。

### 这一关要建立的认识

> WorkBuddy 不只是和你聊天，它可以围绕一个真实项目目录来理解和推进工作。

---

# Exercise 1｜先把项目背景弄明白

有了整体印象以后，再让它把项目背景认真读一遍。

可以这样说：

```text
那先把 00-项目背景 里的几份材料认真看一下，帮我把这个项目捋清楚。

我现在最想知道三件事：
1. 这个项目到底要解决什么问题；
2. 现在已经明确了什么；
3. 哪些还只是说法、假设或者信息不足，暂时不能下结论。

先不用写正式报告，也不要改原始材料。
```

### 你要检查什么

一个合格的回答至少应该知道：

- 当前任务是先识别问题，而不是直接给客户最终方案；
- 样本不能代表整个全国网络；
- 客户提出的几个假设还没有被验证；
- 不应该看到两个指标同时变化，就直接说存在因果关系。

### 这一关练什么

- 先把相关资料和背景给到 Agent；
- 先建立共同理解，再往下做；
- 接受“现在还不知道”这种答案。

---

# Exercise 2｜先把前任留下的交接捋顺

接下来从一份最典型的真实工作材料开始：

`01-待处理资料/01-项目交接记录.md`

这次不是让它“随便总结一下”，而是按照你接手项目真正需要的方式整理。

可以这样说：

```text
我先从前任留下的交接记录开始。
你把 01-待处理资料/01-项目交接记录.md 看一遍，帮我整理成四块：
- 已知事实；
- 明确待办；
- 项目风险；
- 待确认事项。

有几个地方注意一下：
- 原文没说清楚的负责人、日期、数字或原因，不要替我补；
- 前任自己的判断、客户或经销商的说法，和已经确认的事实要分开；
- 跟当前研究关系很弱的事情别放在核心位置。

整理好后放到 03-output/项目交接整理_v1.md。
```

### 完成后马上打开文件检查

重点看四件事：

1. 有没有把“个人感觉”写成事实；
2. 有没有替“还没人负责”的事项编一个负责人；
3. 有没有把“明年网点增加 30%”当成正式计划；
4. 有没有把会议室之类的边缘信息和核心研究事项混在一起。

### 这一关练什么

> **做什么 + 有什么 + 怎么样。**

比“帮我整理一下”更清楚，但也不需要把 Prompt 写成一份需求文档。

---

# Exercise 3｜把四个区域放在一起看

现在看：

`01-待处理资料/02-区域访谈/`

这里有四份区域访谈。真正有价值的不是把四份材料各自缩短一遍，而是看它们放在一起以后能发现什么。

可以这样说：

```text
接下来把 01-待处理资料/02-区域访谈 里的四份材料一起看看。

我不想要四份摘要简单拼在一起，更想知道：
1. 哪些问题在多个区域反复出现；
2. 哪些地方差异很明显；
3. 不同材料之间有没有互相矛盾、或者说法不一样的地方；
4. 现在还有哪些问题证据不够，后面需要继续验证。

访谈里的观点和已经确认的事实要分开。
如果同一个区域内部自己就有不同意见，也保留下来，不要为了总结强行合成一个说法。

先做到这一步，不写最终报告。
结果放到 03-output/区域访谈综合_v1.md。
```

### 你要观察什么

如果 WorkBuddy 只是把四份材料分别摘要一遍，还不算真正完成。

好的综合应该能看出：

- 哪些问题跨区域重复出现；
- 华东、华南、西南、华北不是同一种压力；
- 关于总部线索、库存和轻量网点，不同区域存在不同说法；
- 如果一个区域内部自己就有不同意见，也应该保留这种差异；
- 有些问题需要数据验证，不能只凭访谈定结论。

### 这一关练什么

> Agent 可以一次处理一组材料，但大工作仍然可以一步一步推进。

我们现在只是“综合访谈”，还没有让它直接写最终报告。

---

# Exercise 4｜有样例，就直接给它看

现在你已经有两个中间成果：

- `项目交接整理_v1.md`
- `区域访谈综合_v1.md`

项目目录里还有：

- `02-参考样例/优秀内部项目简报样例.docx`

与其跟 WorkBuddy 说十遍“专业一点”“像咨询公司一点”，不如直接把一个你认可的样子给它看。

可以这样说：

```text
前面的交接整理和区域访谈综合先用这两份。
我现在想做一版内部项目简报，给项目组开会时快速看。

内容基于：
- 03-output/项目交接整理_v1.md
- 03-output/区域访谈综合_v1.md

02-参考样例/优秀内部项目简报样例.docx 是以前项目的一份材料。
你参考它的结构、信息密度和表达方式就行，不要把里面的业务内容带进来。

新岚项目里哪些是事实、哪些是访谈观点、哪些还要验证，继续分清楚。
先做一版，保存为 03-output/内部项目简报_v1.docx。
```

### 为什么要给样例

因为：

> “照这个样例的结构和信息密度做”

通常比：

> “专业一点、高级一点、像咨询公司一点”

更明确。

---

# Exercise 5｜第一版先别急着满意

现在打开 `内部项目简报_v1.docx`，自己先看一遍。

至少看：

- 有没有把访谈观点写成确定事实；
- 有没有漏掉重要区域差异；
- 有没有出现原始材料中不存在的数据、人名、日期或原因；
- 有没有把样本说成全国水平；
- 有没有把“某个人这样说”写成“这个区域都这样”，甚至“几个区域都这样”；
- 是否过长；
- 是否真正参考了样例的结构。

然后把你真正看到的问题告诉 WorkBuddy。

比如你看下来确实有这三个问题，就可以这样说：

```text
这版先别覆盖，我看下来有几个地方需要改：

1. 总部线索那部分说得有点太确定了，四个区域其实不是同一种说法；
2. 西南的售后服务半径问题不够突出；
3. 结尾还缺一组清楚的待验证问题。

你按这三个问题改一版，其他没有问题的地方尽量别乱动。
保留现在的 v1，新版保存成 03-output/内部项目简报_v2.docx。
```

### 这一关最重要的认识

> 第一个回答只是起点。

正确工作方式是：

**先出一版 → 人检查 → 给具体反馈 → 再改。**

同时保留 `v1`，避免一改就把原来的可用版本覆盖掉。

---

# Exercise 6｜换了一件事，就换一个 Task

最后做一个独立小任务。

这已经不是在继续修改“项目简报”了，所以**新建一个 WorkBuddy Task**，仍然使用同一个项目目录。

只看：

`01-待处理资料/04-图片资料/区域经营指标截图.png`

可以这样说：

```text
这张区域经营指标图我想单独看一下。
你先只基于这张图，帮我说清楚三件事：
1. 图里能直接确认什么；
2. 哪些东西仅靠这张图其实还不能确认；
3. 如果我还想往下判断原因，接下来需要补什么数据。

看到两个指标一起高或者一起低，也先别直接解释成因果关系。
```

### 这一关练什么

- 同一件事连续修改：继续原 Task；
- 明显换了一件事：新建 Task；
- 不要把所有工作都堆在一个越来越混乱的会话里。

---

# 培训结束后，你至少应该会这些

- 能把一个真实文件夹交给 WorkBuddy 工作；
- 知道先让 Agent 理解资料，再执行；
- 能引用一个文件，也能让它处理一整个文件夹；
- 能用“做什么 + 有什么 + 怎么样”描述任务；
- 会把大工作拆成几步；
- 会给参考样例；
- 会检查 AI 有没有编造、遗漏或越过证据边界；
- 会用具体反馈让它继续改；
- 会保留 v1 / v2；
- 知道明显换任务时应该新建 Task。

**你不需要在第一次培训里学会 Skill、Connector、Automation、API、Git、CLI 或任何编程知识。**
