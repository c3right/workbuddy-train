# 第一次培训实操手册

> 适用对象：第一次从“网页聊天型 AI”转向 WorkBuddy 的同事  
> 本次目标：**不是学完所有功能，而是亲手跑通一次 Agent 工作闭环。**

---

## 0. 先记住这一张图

```text
先选对工作目录
→ 让 Agent 先看懂资料
→ 把大工作拆成小任务
→ 说清楚：做什么 / 有什么 / 怎么样
→ 让 Agent 生成或修改真实文件
→ 人检查事实、逻辑和边界
→ 具体指出问题，继续改
→ 重要文件保留 v1 / v2
→ 换了一件事，就换一个 Task
```

你不需要背术语，也不需要追求“神 Prompt”。这次只练正确的工作方法。

---

## 1. 打开练习项目

在 WorkBuddy 中选择整个：

`WorkBuddy-L1-Lab/`

作为本次工作的目录。

目录中已经有：

- `00-项目背景/`：项目是什么、客户在问什么、研究边界是什么；
- `01-待处理资料/`：交接记录、四份区域访谈、Excel、图片；
- `02-参考样例/`：另一项目的优秀内部简报，只用于参考结构和信息密度；
- `03-output/`：你让 WorkBuddy 生成的成果放这里。

**原则：不要修改原始资料。**

---

# Exercise 0｜先看，不要急着动手

第一步只让 WorkBuddy 看目录。

可以这样说：

```text
先查看当前工作目录里有什么，告诉我各个目录大致是什么用途。
不要修改或生成任何文件。
```

### 你要观察什么

- 它有没有识别到几个主要目录；
- 它是否真的在看工作目录，而不是只回答常识；
- 它有没有遵守“先不要修改文件”。

### 这一关要建立的认识

> WorkBuddy 不只是和你聊天，它是在这个工作目录里围绕任务做事。

---

# Exercise 1｜先把项目看懂

这一步只读 `00-项目背景/`。

示例说法：

```text
先阅读 00-项目背景 里的材料。

告诉我：
1. 这个项目要解决什么问题；
2. 已经明确了什么；
3. 哪些事情现在还不能下结论。

暂时不要写正式报告，也不要修改原始文件。
```

### 你要检查什么

一个合格的回答至少应该知道：

- 当前任务是先识别问题，而不是直接给客户最终方案；
- 样本不能代表整个全国网络；
- 客户提出的几个假设还没有被验证；
- 不应该看到两个指标同时变化，就直接说存在因果关系。

### 这一关练什么

- 给 Agent 足够的 Context；
- 先建立共同理解；
- 接受“现在还不知道”这种答案。

---

# Exercise 2｜单文件：从乱材料里提取有用信息

现在只处理：

`01-待处理资料/01-项目交接记录.md`

任务不是“总结一下”，而是按工作需要提取。

示例说法：

```text
请阅读 01-待处理资料/01-项目交接记录.md。

把内容整理为：
- 已知事实；
- 明确待办；
- 项目风险；
- 待确认事项。

要求：
- 原文没有明确的负责人、日期、数字或原因，不要自行补全；
- 区分事实、前任成员的个人判断和未经证实的说法；
- 与当前研究任务关系很弱的信息不要放在核心位置；
- 保存到 03-output/项目交接整理_v1.md。
```

### 完成后马上打开文件检查

重点看四件事：

1. 有没有把“个人感觉”写成事实；
2. 有没有替“还没人负责”的事项编一个负责人；
3. 有没有把“明年网点增加 30%”当成正式计划；
4. 有没有把会议室之类的边缘信息和核心研究事项混在一起。

### 这一关练什么

> **做什么 + 有什么 + 怎么样。**

比“帮我整理一下”更清楚，但也不需要写几十行 Prompt。

---

# Exercise 3｜整个文件夹：不是拼摘要，而是找模式

现在处理：

`01-待处理资料/02-区域访谈/`

这里有四份区域访谈。

示例说法：

```text
阅读 01-待处理资料/02-区域访谈 里的四份材料。
不要直接写最终报告。

先整理：
1. 多个区域反复出现的问题；
2. 不同区域明显不同的情况；
3. 材料之间存在的矛盾或不同说法；
4. 目前证据不足、下一步需要验证的问题。

注意区分访谈观点和已经确认的事实。
结果保存到 03-output/区域访谈综合_v1.md。
```

### 你要观察什么

如果 WorkBuddy 只是把四份材料分别摘要一遍，还不算真正完成。

好的综合应该能看出：

- 哪些问题跨区域重复出现；
- 华东、华南、西南、华北不是同一种压力；
- 关于总部线索、库存和轻量网点，不同区域存在不同说法；
- 有些问题需要数据验证，不能只凭访谈定结论。

### 这一关练什么

> Agent 可以一次处理一组材料，但大任务仍然要拆步骤。

我们现在只是“综合访谈”，还没有让它直接写最终报告。

---

# Exercise 4｜给一个好样例，比说十句“专业一点”更有效

现在你已经有两个中间成果：

- `项目交接整理_v1.md`
- `区域访谈综合_v1.md`

再加上：

- `02-参考样例/优秀内部项目简报样例.docx`

让 WorkBuddy 生成一份内部简报第一版。

示例说法：

```text
请基于：
- 03-output/项目交接整理_v1.md
- 03-output/区域访谈综合_v1.md

生成一份内部项目简报。

结构、信息密度和表达方式参考：
02-参考样例/优秀内部项目简报样例.docx

要求：
- 业务事实只能来自当前新岚汽车项目材料；
- 不要复制参考样例中的业务内容；
- 区分事实、访谈观点和待验证问题；
- 结果用于内部项目会快速阅读；
- 保存为 03-output/内部项目简报_v1.docx。
```

### 为什么要给样例

因为：

> “照这个样例的结构和信息密度做”

通常比：

> “专业一点、高级一点、像咨询公司一点”

更明确。

---

# Exercise 5｜第一版不是终点：Review → v2

现在不要马上满意，也不要马上重写一大段 Prompt。

打开 `内部项目简报_v1.docx`，先自己检查。

至少看：

- 有没有把访谈观点写成确定事实；
- 有没有漏掉重要区域差异；
- 有没有出现原始材料中不存在的数据、人名、日期或原因；
- 有没有把样本说成全国水平；
- 是否过长；
- 是否真正参考了样例的结构。

然后把你发现的问题**具体告诉 WorkBuddy**。

例如：

```text
请修改刚才的简报，但不要覆盖 v1。

我发现三个问题：
1. 对总部线索的表述太确定，四个区域其实存在不同说法；
2. 没有突出西南的售后服务半径问题；
3. 结尾缺少明确的待验证问题。

请修正，并新建：
03-output/内部项目简报_v2.docx
```

### 这一关最重要的认识

> 第一个回答只是起点。

正确工作方式是：

**先出一版 → 人检查 → 给具体反馈 → 再改。**

同时保留 `v1`，避免一改就把原来的可用版本覆盖掉。

---

# Exercise 6｜换任务，换一个 Task

最后做一个独立小任务。

不要继续塞进前面的“项目简报”长会话里，**新建一个 WorkBuddy Task**，仍然使用同一个项目目录。

只分析：

`01-待处理资料/04-图片资料/区域经营指标截图.png`

示例说法：

```text
请只分析这张区域经营指标截图。

告诉我：
1. 图里可以直接确认什么；
2. 图里不能确认什么；
3. 如果要进一步判断原因，还需要哪些数据。

不要把相关关系写成因果关系。
```

### 这一关练什么

- 同一件事连续修改：继续原 Task；
- 明显换了一件事：新建 Task；
- 不要把所有工作都堆在一个越来越混乱的会话里。

---

# 培训结束后，你至少应该会这些

- 能把一个真实文件夹交给 WorkBuddy 工作；
- 知道先让 Agent 理解资料，再执行；
- 能引用一个文件，也能让它处理一整个文件夹；
- 能用“做什么 + 有什么 + 怎么样”描述任务；
- 会把大工作拆成几步；
- 会给参考样例；
- 会检查 AI 有没有编造、遗漏或越过证据边界；
- 会用具体反馈让它继续改；
- 会保留 v1 / v2；
- 知道明显换任务时应该新建 Task。

**你不需要在第一次培训里学会 Skill、Connector、Automation、API、Git、CLI 或任何编程知识。**
