# 第一次培训｜讲师手册

> 培训对象：主要为研究员，同时兼容行政、数据分析岗位；默认只有网页端大模型聊天经验。  
> 培训目标：完成“认知重塑 + L1 工具跑起来”。L2 只由讲师演示。

---

## 1. 这次培训不要讲成“软件功能介绍”

整场课只围绕一个问题：

> **怎样正确带着一个 Agent 做事情？**

推荐主线：

```text
网页聊天
↓
真实工作目录
↓
先理解资料
↓
拆任务
↓
生成真实文件
↓
人工验收
↓
继续修改
↓
保留版本
↓
换任务时换 Task
```

不要在第一次培训展开：Git、CLI、subagent、API 原理、MCP 原理、Python/npm、复杂 Skill、自动化搭建。

---

## 2. 建议节奏

不把时间卡死，建议按 75—100 分钟准备，可根据现场缩短。

### A. 认知重塑：15—20 分钟

只讲四件事：

1. 网页聊天是“我问，它答”；Agent 是围绕目标、资料和文件持续做事；
2. Workspace 是它工作的“桌面”；
3. Context 可以理解为“这件事它现在拿到了什么资料和要求”；
4. 人不是把责任交出去，而是把部分工作交出去，最终仍要验收。

可以用一句话解释：

> “大模型像大脑，WorkBuddy 让它能围绕一个工作目录看材料、用工具、生成和修改文件。”

### B. L1 全员跟做：45—60 分钟

依次做 Exercise 0～6。

### C. L2 讲师 Demo：15—20 分钟

演示一个完整的小型研究任务：先 Plan → 证据矩阵 → 人工 Gate → 短研究报告 v1 → Review → v2。

---

## 3. 讲师必须守住的教学原则

### 3.1 不展示“神 Prompt”

学员必须知道提示词不是密码。

同一个任务可以有不同自然语言表达，只要说清楚：

- 做什么；
- 有什么；
- 怎么样。

### 3.2 一定要出现一次不完美结果

不要把现场演示优化成“一遍完美”。

如果 v1 真的很好，也要主动找一个可改进点，例如：

- 某个判断过度；
- 漏了区域差异；
- 证据来源没说清楚；
- 输出太长。

然后现场让 Agent 修正。

### 3.3 失败不要藏

如果出现：

- 找错文件；
- 没按要求保存；
- 把观点当事实；
- 格式不理想；
- 结果过长；

优先把它当教材，问大家“下一步应该怎么告诉它”。

### 3.4 不让学员只看聊天窗口

反复提醒大家观察：

- 它读了哪些文件；
- 它创建了哪些文件；
- 它是否动了原始文件；
- 输出到底保存在哪里；
- v1 是否还在。

### 3.5 不讲技术底层来解释每个现象

第一次培训只建立操作习惯。

例如不要讲 context window/token，只说：

> “同一件事继续聊；明显换一件事，就换一个 Task。”

---

# 4. Exercise 0｜认识工作区

## 讲师动作

让所有人把 `WorkBuddy-L1-Lab/` 作为当前工作目录。

让大家输入类似：

```text
先查看当前工作目录里有什么，告诉我各个目录大致是什么用途。
不要修改或生成任何文件。
```

## 现场追问

- “刚才它回答的是网上查的，还是我们目录里的？”
- “为什么我要特意说先不要修改文件？”

## 希望学员得到的结论

> Agent 能对一个真实工作目录采取行动，因此第一步可以只是理解，不必马上执行。

---

# 5. Exercise 1｜先理解项目

让学员读 `00-项目背景/`。

这一关不要产文件，只让大家确认：

- 项目当前是问题识别，不是给最终方案；
- 12 家样本不能代表全国约 260 个网点；
- 客户提出的三个假设不是项目结论；
- 访谈观点和数据事实要区分。

## 现场教学句

> “很多人刚用 Agent，会第一句话就说‘把这些资料做成完整报告’。我们今天故意不这样做。先把问题和边界看懂。”

---

# 6. Exercise 2｜单文件提取

目标输出：

`03-output/项目交接整理_v1.md`

重点观察：

- 是否识别周五阶段会；
- 是否把库存口径、优惠率口径列为待确认；
- 是否把前任“我感觉最核心还是价格战”保留为个人判断；
- 是否拒绝使用“明年网点增加 30%”这种无正式来源说法；
- 是否没有自作主张给无人负责事项补负责人。

如果 Agent 错了，不要立刻告诉标准答案。先问学员：

> “这里是哪一类错误？我们应该怎样具体反馈？”

---

# 7. Exercise 3｜整个文件夹综合

目标输出：

`03-output/区域访谈综合_v1.md`

这一关最重要的是防止“4 份摘要拼接”。

讲师要引导大家找三种东西：

1. **共性**：例如多个区域都出现价格竞争/盈利或固定成本压力；
2. **差异**：华东库存明显，西南服务覆盖更突出，华北库存相对稳定；
3. **冲突/不同说法**：线索到底是质量问题还是门店跟进问题，各区域说法并不一致。

## 关键提醒

不要追求“得出一个全国结论”。这个练习的好结果反而应该保留“不一样”。

---

# 8. Exercise 4｜给样例生成 v1

输入：

- `项目交接整理_v1.md`
- `区域访谈综合_v1.md`
- `优秀内部项目简报样例.docx`

输出：

`内部项目简报_v1.docx`

讲师重点解释：

> “资料不仅可以告诉 AI‘事实是什么’，也可以告诉 AI‘做成什么样’。”

强调：参考样例的业务内容与新岚汽车无关，只学结构、信息密度和表达方式。

---

# 9. Exercise 5｜Review → v2

必须让学员先自己看 v1。

统一检查：

- 是否把访谈观点写成事实；
- 是否把样本推成全国；
- 是否遗漏区域差异；
- 是否出现材料中没有的数字/人名/日期/原因；
- 是否过长；
- 是否真正参考样例结构。

然后让学员给具体修改意见，并明确：

> 保留 `v1`，新建 `内部项目简报_v2.docx`。

讲师可现场展示：

- “不够专业，再改改”是低质量反馈；
- “线索问题表述过度、漏掉西南售后半径、结尾缺少待验证事项”是高质量反馈。

---

# 10. Exercise 6｜换任务，换 Task

新建 Task，只分析：

`区域经营指标截图.png`

图中可以直接读出的区域均值约为：

- 华东：月均零售/店约 41.3 台，库存周转约 61.7 天，优惠率 8.6%；
- 华南：约 46.3 台、51.7 天、7.9%；
- 西南：约 33.3 台、47.7 天、6.7%；
- 华北：约 38.0 台、44.0 天、5.8%。

但要强调：

- 这是 12 家示例门店的 2026 年 7—8 月平均；
- 不代表全国；
- 图上两个指标一起高/低，不代表因果关系。

这一关不是教数据分析，而是教：

> “明显换一件事，别在旧会话里一直堆。”

---

# 11. L2 Demo

按 `instructor/L2演示脚本.md` 执行。

核心不是再多展示功能，而是让学员看到：

> L1 的单步能力组合起来，就能承担一个完整的小型业务任务。

L2 不生成 PPT，不做联网补充，不引入 Skill、Connector、subagent 或代码。

---

# 12. 培训结束时的收口

最后不要总结十几个功能。

只让大家记住这五句话：

1. **先把工作目录给对。**
2. **先让它看懂，再让它做。**
3. **大任务拆小步，一次推进一件事。**
4. **第一版只是起点，人要检查并具体反馈。**
5. **重要成果保留版本；明显换任务就换 Task。**

如果大家能把这五句话带回自己的日常工作，第一次培训就算成功。
