# L2 演示脚本｜从局部操作到完整小型业务任务

> 形式：讲师演示，不要求学员现场独立完成。  
> 建议时长：15—20 分钟。  
> 最终交付：**短研究报告**，不生成 PPT。  
> 本 Demo 不联网、不引入 Skill / Connector / subagent / 代码。

---

## 1. L2 要让学员看到什么

L1 解决的是：

> “我会让 Agent 看资料、完成一个明确动作、生成并修改文件。”

L2 要展示的是：

> “我可以把一个边界清楚的小型业务任务交给 Agent，但不是一键交付；先规划、再组织证据、人工把关、再形成报告。”

主线：

```text
完整任务
→ Plan
→ 人工确认计划
→ 证据矩阵
→ 人工 Gate
→ 短研究报告 v1
→ Review
→ 短研究报告 v2
```

---

# 2. Demo 任务

新建一个 WorkBuddy Task，继续使用同一个 `WorkBuddy-L1-Lab/` 项目目录。

讲师先说明：

> “这是一个新的完整业务任务，所以我新开一个 Task；但所有资料仍然来自同一个项目目录。”

任务定义：

> **基于现有材料，对新岚汽车四个区域的渠道经营压力做一次初步研究判断，回答‘四区是否是同一个问题、客户三个初始假设目前得到多少支持、下一步最值得验证什么’，最终形成一份内部短研究报告。**

不是要给客户最终解决方案。

---

# 3. Step 1｜先 Plan，不执行

切到 Plan（或明确要求“先只给计划”）。

建议输入：

```text
我要基于当前工作目录，完成一份《新岚汽车渠道经营问题初步研究报告》。

报告要回答：
1. 四个区域是否面对同一种渠道经营问题；
2. 各区域最突出的压力分别是什么；
3. 客户提出的三个假设，目前分别得到什么程度的支持；
4. 哪些判断证据不足；
5. 下一步优先验证什么。

可使用：
- 00-项目背景；
- 01-待处理资料中的项目交接记录；
- 四份区域访谈；
- 区域渠道经营快照.xlsx；
- 区域经营指标截图.png。

约束：
- 样本不能代表全国；
- 访谈观点和数据事实要区分；
- 不把相关关系写成因果；
- 不补充材料中没有的数字或事实；
- 本次不做外部网络搜索。

先不要生成报告，也不要修改文件。
请先告诉我你准备怎么做、会先检查哪些口径和风险。
```

## 讲师现场检查 Plan

一个合格 Plan 至少应该包含：

- 先确认项目边界和口径；
- 读取四区访谈并做对比；
- 读取 Excel / 图表，而不是只看访谈；
- 区分事实、观点、假设、待验证项；
- 先做中间分析，再写最终报告；
- 明确样本不能推全国；
- 不直接做因果推断。

如果 Plan 一上来就是“读取后直接写报告”，讲师现场追加：

> “先增加一个证据整理步骤，不要跳过中间分析。”

### 教学点

复杂一点的任务，不必第一句就让 Agent 开始写最终成果。

> **先商量怎么做，比做坏以后再返工便宜。**

---

# 4. Step 2｜先生成证据矩阵

确认 Plan 后进入执行。

建议输入：

```text
按刚才确认的计划，先完成第一步分析，不写最终报告。

请把关键证据整理成：
03-output/L2-证据矩阵_v1.md

至少覆盖：
- 四区主要经营压力；
- 库存；
- 价格/优惠；
- 总部线索与门店执行；
- 固定成本；
- 县域覆盖与轻量网点；
- 售后服务覆盖。

每个重要判断尽量注明：
- 来自哪个文件；
- 属于数据事实、访谈观点、客户假设还是初步判断；
- 有什么限制或冲突。

完成证据矩阵后停下来，不要继续写报告。
```

---

# 5. Step 3｜人工 Gate：先检查证据，再批准写报告

打开 `L2-证据矩阵_v1.md`。

讲师不要逐字审稿，只检查 6 个高风险点：

1. **样本边界**：有没有把 12 家示例门店写成全国；
2. **库存**：有没有看出华东明显高、华北相对稳定，而不是写成全国库存问题；
3. **线索**：有没有保留“线索质量 vs 门店首响/跟进”的不同说法；
4. **轻量网点**：有没有保留四区态度差异，而不是写成“大家都支持”；
5. **未经证实数字**：有没有把“无效线索接近三成”“明年网点增加 30%”写成事实；
6. **因果**：有没有因为优惠率、零售、库存同时变化就直接下因果结论。

如果发现问题，当场纠正。例如：

```text
先不要写报告。
证据矩阵里有两处需要修正：
1. “总部线索不足”不能作为四区共性结论，要保留各区域不同说法；
2. 华南“无效线索接近三成”只是访谈中的口头估计，不能当成已验证数据。

请先修正证据矩阵。
```

### 教学点

> **人要在关键节点把关，而不是等最终报告做完才发现证据基础错了。**

---

# 6. Step 4｜生成短研究报告 v1

证据矩阵通过后，再批准写报告。

建议输入：

```text
现在基于已经修正的证据矩阵和原始材料，生成一份内部短研究报告：

03-output/L2-渠道经营问题初步研究报告_v1.docx

建议结构：
1. 核心判断；
2. 四区域主要差异；
3. 对客户三个初始假设的初步判断；
4. 目前证据不足的地方；
5. 下一步优先验证事项；
6. 样本与方法限制。

要求：
- 约 1200—1800 字，内部快速阅读；
- 先给判断，再给证据；
- 重要判断尽量能看出依据来自哪些材料；
- 明确区分事实、访谈观点、初步判断；
- 不给“全国渠道应该怎么改”的最终方案；
- 不做复杂排版，以内容清楚为优先。
```

### 讲师提示

如果 WorkBuddy 对 DOCX 生成表现异常，不要转向 PPT或现场排查复杂格式。可以直接要求：

> “先以 Markdown 内容完成报告，格式问题不作为本次演示重点。”

这不是失败。本 Demo 的教学重点是**研究流程与证据控制**。

---

# 7. Step 5｜Review v1

打开报告，重点检查：

- 开头是否真正回答“四区是不是同一个问题”；
- 有没有把某个单一区域现象当成全国主因；
- 对三个客户假设是否有“支持 / 部分支持 / 证据不足”的区分；
- 有没有保留华东、华南、西南、华北的不同结构；
- 下一步验证是否具体；
- 是否明确写了样本限制。

## 预期合理的核心判断

方向应该接近：

> 现有材料不支持把新岚汽车渠道压力归结为单一全国性问题。四区都存在经营压力，但压力形态不同：华东更突出库存结构、价格与盈利；华南更突出促销、线索运营与门店执行；西南更突出服务覆盖和轻量渠道履约责任；华北在库存相对稳定的情况下仍受固定成本、价格竞争和执行效率影响。

不要求逐字一致。

---

# 8. Step 6｜具体反馈，生成 v2

不要说：

> “还是不够好，再专业一点。”

要示范具体反馈。

例如根据现场 v1 选择 2—3 个真实问题：

```text
请保留 v1，不要覆盖。

针对下面问题修订：
1. 对“总部线索不足”的判断仍然太确定，请改成对四区不同证据的比较；
2. 西南部分要补充“销售触点更近不等于整体渠道效率一定更高”的证据边界；
3. 下一步验证事项太泛，请压缩为 4—5 个可以直接继续查的数据/问题。

生成：
03-output/L2-渠道经营问题初步研究报告_v2.docx
```

如果 v1 已经很好，可以把 Review 重点放在：

- 压缩长度；
- 增加来源提示；
- 把过度断言改为有边界的判断；
- 把下一步验证写得更可执行。

---

# 9. Demo 收口：让学员看到 L1 → L2 的升级

最后只比较两层：

## L1

```text
看一个目录
→ 读一个文件
→ 综合一个文件夹
→ 用样例生成文件
→ Review
→ v2
```

## L2

```text
一个完整业务问题
→ 先规划
→ 多类型材料共同使用
→ 证据矩阵
→ 人工 Gate
→ 研究判断
→ 短报告
→ Review
→ v2
```

讲师收尾一句话：

> **“L2 并不是多会几个按钮，而是开始知道怎样把一个完整工作拆成 Agent 能稳定承担、自己又能控制质量的过程。”**

---

# 10. Demo 明确不做的事

为了避免把第一次培训带偏，本演示不加入：

- PPT 生成；
- 外部 Web 搜索；
- Skill 制作；
- Connector；
- Automation；
- subagent；
- Git；
- CLI；
- Python / npm；
- 复杂数据建模。

这些都不是 L2 Demo 要证明的东西。
