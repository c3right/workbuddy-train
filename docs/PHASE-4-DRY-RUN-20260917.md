## 2. L1 Dry Run

### Exercise 0｜认识工作区

结果：完成。

观察：原提示词只要求“查看目录”，实际 Agent 主动读取了部分文件内容，并提前识别出库存口径冲突等后续信息。

修订：Exercise 0 改为只查看文件夹与文件名称，暂不打开正文。

### Exercise 1｜先理解项目

结果：完成。

Agent 能正确识别：

- 当前阶段是问题识别，不是最终方案；
- 样本不能代表全国网络；
- 客户三个假设尚未验证；
- 存在库存、优惠率、线索等口径与证据边界问题。

### Exercise 2｜单文件提取

结果：完成。

产出：`03-output/项目交接整理_v1.md`

表现：能区分事实、未经核实说法与个人判断；未自行补全负责人、日期或无出处数字；能把边缘事项降级处理。

### Exercise 3｜整个文件夹综合

结果：完成，但暴露一次“过度综合”风险。

产出：`03-output/区域访谈综合_v1.md`

观察：Agent 将华东、华南、华北各一位受访者关于门店响应/跟进的观点进一步概括为跨区域模式，但华东与华南区域内部本身存在相反意见。

修订：

- 学员提示增加：同一区域内部若存在不同说法，要保留差异，不要为了总结强行合并；
- Review 检查增加：不要把某个人的说法升级成区域或跨区域共性。

### Exercise 4｜参考样例生成 v1

结果：完成。

产出：`03-output/内部项目简报_v1.docx`

表现：参考了样例的结构与信息密度，没有复制样例业务内容。

### Exercise 5｜Review → v2

结果：完成。

产出：`03-output/内部项目简报_v2.docx`

表现：人工具体反馈能够有效修正判断强度、突出区域差异，并保留 v1。

### Exercise 6｜换任务，换 Task

结果：完成。

观察：新 Task 只基于图片分析时，没有自动借用旧 Task 对百分比指标的解释；能区分“图片直接可确认”与“需要补充信息才能判断”。

## 3. L2 Dry Run

### Step 1｜Plan

结果：Plan 本身合格。

异常：Plan 后 Agent 提出两个确认问题；人工回复“都按你建议的来，继续”时，Agent准备直接进入报告写作。人工及时停止。

判断：这既可能受模型主动性影响，也说明阶段授权语言需要更明确。

修订：

- Plan 提示增加“给出计划后停止，不执行任何计划步骤”；
- 讲师下一步固定为明确授权：只生成证据矩阵，完成后停下来，不写报告。

### Step 2｜证据矩阵

结果：完成。

产出：`03-output/L2-证据矩阵_v1.md`

矩阵覆盖库存、价格/优惠、线索、成本、轻量网点、售后等主题，并登记来源、性质、限制、冲突和待补数据。

### Step 3｜人工 Gate

结果：有效。

人工要求 Agent 再检查两处风险。Agent 发现并修正：

- “三区有人指向门店执行”被概括成跨区模式的问题；
- 华南“无效线索接近三成”进一步收紧为单一受访者口头估计，不进入报告正文。

这一步证明：中间产物本身也需要验收；但该方法作为讲师后台控制点，不扩展成第一次培训的复杂理论。

### Step 4｜短研究报告 v1

结果：完成。

产出：`03-output/L2-渠道经营问题初步研究报告_v1.docx`

Agent 因字数偏长自行压缩两轮，最终形成约 1812 字的内部研究报告。

### Step 5｜Review v1

结果：完成。

人工主要检查判断边界和区域差异，不做文字层面的逐句重写。

### Step 6｜短研究报告 v2

结果：完成。

产出：`03-output/L2-渠道经营问题初步研究报告_v2.docx`

主要修订：

- 线索假设从“未获支持”调整为“四区证据不一致，暂不能支持也不能否定”；
- 增加四区线索证据比较；
- 增加西南“销售触点更近不等于整体渠道效率一定更高”的边界；
- 下一步验证压缩为 5 个可执行事项。

v2 因增加比较表增长到约 2288 字。判断：不应为了机械满足 1800 字而删掉重要证据边界，因此报告长度规则改为“正文尽量 1200—1800 字，必要比较表可保留”。

## 4. Phase 4 Judgement

### Accepted

以下设计保持不变：

- 第一次培训继续只做“认知重塑 + L1 工具跑起来”；
- 学员心智地图保持简单；
- 一个连续咨询项目贯穿全部练习；
- L1 Exercise 0—6 顺序不变；
- L2 仍是讲师演示；
- L2 采用 `Plan → 证据矩阵 → 人工 Gate → 报告 v1 → Review → v2`；
- 不加入 PPT、Web Search、Skill、Connector、Automation、Git、CLI、subagent 或开发环境教学。

### Lightweight Revisions

仅做以下跨模型、低复杂度修订：

1. Exercise 0 适度限制为“只看目录和文件名”；
2. Exercise 3 提醒保留同一区域内部不同说法；
3. Exercise 5 增加“不要把少数人观点升级成区域/跨区共性”的检查；
4. L2 Plan 明确“完成后停止，等待人工授权”；
5. L2 Gate 增加“少数观点被放大”和“证据不足被误写成否定结论”两项检查；
6. L2 v2 修改提示改为“看是否存在下面问题，如有则修订”，避免为了演示而强造错误；
7. 报告字数从硬上限改为快速阅读导向，必要比较表允许保留。

## 5. Training Design Principle After Dry Run

本轮不把深层的证据治理和流程控制理论加入学员心智地图。

第一次培训仍然只要求小白先跨过一层：

> **AI 不只是网页聊天；WorkBuddy 可以围绕真实工作目录，和你一起把事情一步一步做出来。**

更严格的质量控制留在讲师脚本和课程后台：

> **后台方法可以严，前台教学不要重。**
